# AGENTS.md

Guidance for coding agents (and humans) working in this repository.
CONTRIBUTING.md has the same material with more context.

## What this is

`OnetimeSecret`: the official PowerShell module for the Onetime Secret API
v2. Cmdlets use the `Ots` noun prefix (`New-OtsSecret`, `Get-OtsReceipt`).
No dependencies beyond `Invoke-WebRequest`; runs on Windows PowerShell 5.1
and PowerShell 7+ on Windows, macOS and Linux. One of a family of SDKs
(`onetimesecret-py`, `onetimesecret-js`, `onetimesecret-rust`,
`onetimesecret-ruby`, ...) that share env var names, auth and error
semantics, but it is idiomatic PowerShell, not a port.

## Commands

```powershell
./build.ps1 -Bootstrap        # install InvokeBuild, Pester 5, PSScriptAnalyzer, platyPS (CurrentUser)
./build.ps1                   # Analyze + Test; run before finishing
./build.ps1 -Task Build       # stage the single-file module under output/
./build.ps1 -Task Docs        # regenerate docs/cmdlets from comment-based help
Import-Module ./src/OnetimeSecret/OnetimeSecret.psd1 -Force   # try it
```

Live tests against a real server's guest endpoints run only with
`OTS_INTEGRATION=1` and `ONETIME_BASE_URL` set.

## Layout

- `src/OnetimeSecret/Public/`: one exported cmdlet per file, named after it.
- `src/OnetimeSecret/Private/`: `Invoke-OtsRequest` (the only HTTP call
  site, retries, error records), converters to typed objects, connection
  resolution.
- `src/OnetimeSecret/OnetimeSecret.psd1`: manifest; `FunctionsToExport` is
  explicit and must match `Public/`.
- `tests/`: Pester 5. `Module.Tests.ps1` is the quality gate (manifest,
  help, analyzer); `Unit/` mocks `Invoke-WebRequest` and asserts on the
  request sent; `Unit/TestHelpers.psm1` holds the canned payloads.
- `docs/cmdlets/`: generated by platyPS. Do not edit; change the
  comment-based help and run `./build.ps1 -Task Docs`.

## Rules

- No syntax newer than Windows PowerShell 5.1 in `src/` (no ternary, `??`,
  `-AsPlainText` on `ConvertFrom-SecureString`, three-argument `Join-Path`).
  The analyzer's compatibility rules catch most of it; CI on 5.1 catches the rest.
- Approved verbs, `[CmdletBinding()]`, `[OutputType()]`, and comment-based
  help with every parameter and at least one example. Destructive cmdlets
  declare `SupportsShouldProcess`.
- Single-item failures go through `$PSCmdlet.ThrowTerminatingError`;
  per-item failures in loops through `$PSCmdlet.WriteError`. API errors are
  built by `New-OtsErrorRecord` (`OnetimeSecret.Api.<error_type>`).
- Only idempotent GETs are retried. Never retry POST or PATCH.
- Never write secret values, passphrases or tokens to Verbose, Warning or
  error output.
- Formatting is `PSScriptAnalyzerSettings.psd1`; warnings fail CI.
- Add a `CHANGELOG.md` line under `## [Unreleased]` for user-visible
  changes. Do not bump `ModuleVersion` in feature work; releases are
  tag-driven, see `docs/releasing.md`.
- Target API v2 only. v3 is unstable and off limits until declared stable.
